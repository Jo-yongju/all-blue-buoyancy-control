G431 엔코더 관찰 기능 / 2026-11-09

대상: firmware/updown_dir_control
기존 STM32CubeIDE 1.17 프로젝트에 통합. 새 프로젝트로 이전하지 않음.

1. 이번 변경과 이유
- 기존 슬라이더 위치 제어, JOG, 조종기/IMU 제어 경로를 유지한다.
- 엔코더는 관찰 전용이다. PWM, 목표 위치, 끝점 이동 허용값을 변경하지 않는다.
- 양끝 ADC가 여러 위치에서 동일하므로 정확한 위치 피드백으로 쓸 수 없다.
  센서1: 0 쪽 약2mm / 4095 쪽 약4mm.
  센서2: 0 쪽 약2mm / 4095 쪽 약3.5mm.
  전체 이동58.48mm와 같은 기준이면 값이 변하는 구간은 대략
  센서1 2~54.48mm, 센서2 2~54.98mm다. 실물 조립 기준으로 재확인한다.
  522/529 중간점과 기존 3점 변환은 남기지만 양끝을 정확한 좌표로 보지 않는다.
- 기존 motor_sign=0, LIVE enable=false를 유지한다. 엔코더 ON/REF로 해제되지 않는다.

2. 구현 범위
Control/encoder_observer: A/B 양쪽 에지 x4 카운트, 방향, 잘못된 상태전이 감지,
  카운터/시간 wrap 처리, 속도(count/s), 수동 기준점에서 이동량 추정.
Core/Src/encoder_port: PC0/PC1 앞 모듈 A/B, PC2/PC3 뒤 모듈 A/B.
  부팅 시 핀을 사용하지 않고 ENC ON에서만 활성화한다.
  EXTI0~3 우선순위6. ISR은 카운트/오류만 갱신하고 통신/RTOS API 호출 없음.
  ControlTask는 짧은 인터럽트 마스킹으로 카운트/오류/AB를 한 번에 읽는다.
App/encoder_service: ControlTask가 설정과 기준점을 단독 소유한다.
  기존10ms 제어 주기에 속도를 계산한다. 10ms는 계측 시작값이지 검증된
  최적 제어 주기가 아니다. 에지는 ISR에서 수집하므로 10ms마다 GPIO를 읽어
  펄스를 세는 방식이 아니다. 표본 간격100ms 초과이면 속도 유효성을 해제한다.
  잘못된 AB 전이 발생 시 기준점/위치 유효성을 해제한다.
  ON/OFF, 재부팅, 환산계수 변경 시 기준점이 사라진다. Flash 저장하지 않는다.

3. 명령 (USB VCP, 기존115200)
ENC HELP
ENC ON
ENC STATUS 1
ENC STATUS 2
ENC SCALE 1 <실측한 부호 있는 counts/mm>
ENC REF 1 <자로 확인한 현재 위치 mm, 0~58.48>
ENC OFF
두번째 축은1 대신2를 사용한다. SCALE/REF/ON/OFF는 정지·ARM 해제 상태에서만
허용한다. STATUS는 JOG 중에도 가능하다. ENC ON은 두 축 설정을 초기화한다.
출력 count는 부호 있는 누적카운트, errors는 불가능한 AB 전이 누적 횟수,
cps는 count/s, pos_um은 추정 위치 마이크로미터(1000um=1mm).
speed_ok/pos_ok/ref가0이면 해당 수치를 위치/속도로 사용하면 안 된다.
count가 정상이어도 봉의 헛돎, 기어 유격, 피스톤 미끄러짐은 검출되지 않을 수 있다.

4. 모터가 오면 확인할 것
- 실제 엔코더 전원과 A/B 출력 전압/회로형식 확인 후 연결. 모터12V와
  엔코더 전원을 혼동하지 않는다. 이 문서의 PC0~3은 MCU 핀명이며
  커넥터 핀 번호나 전기적 호환성을 검증한 배선도가 아니다.
- PC0~3은 현재 프로젝트에서 다른 기능에 사용되지 않음을 확인했다.
  팀 통합 시 같은 번호의 EXTI0~3을 다른 포트에서 사용하지 않아야 한다.
- 출력축 실제1회전의 카운트를 양방향 확인한다. 제조사374표기는
  디코딩 기준에 따라 x4 카운트와 다를 수 있어1496을 확정 입력하지 않는다.
- 조립된 피스톤의 측정 가능한 내부 구간에서 이동mm와 카운트를 비교한다.
  SCALE = 카운트 변화량 / 실제 이동mm. 왕복과 여러 이동거리에서 반복 확인한다.
- 중간의 알려진 위치에서 REF를 지정한다. ADC 0 또는4095로 자동 원점 설정하지 않는다.
- 같은 위치로 되돌렸을 때 자/슬라이더/카운트의 반복오차와 방향전환 유격을 기록한다.
- 최대속도, 두 모터 동시구동에서 errors와 RTOS 주기 초과/스택 여유를 확인한다.
  소프트웨어 EXTI는 너무 빠른 에지를 놓칠 수 있으며 errors=0만으로 누락이
  없다고 증명할 수 없다. 필요 시 핀을 다시 배정해 하드웨어 타이머 엔코더로 바꾼다.

5. 아직 하지 않은 것 / 완료로 보고하면 안 되는 것
- 엔코더 기반 모터 속도 PID 및 슬라이더와 엔코더를 결합한 실제 폐루프 제어.
- 양끝 포화구간에서의 자동 이동, 자동 원점 찾기, 전원 재인가 후 위치 복원.
- 카운트/mm, 실제 기어비와 방향 확인, 기구 오차, 최종 한계값 검증.
- 자동 부력/자세 제어의 수중 성능 검증 및 HOVER 중성부력 보정.
엔코더가 달렸다는 이유만으로60cc 전체 이동을 허용하지 않는다.
우선 관찰로 정확도/재현성을 확인하고 그 결과로 결합 제어 사용 여부를 결정한다.

6. 기능 현황
USB 명령 모터 정/역/정지: 기존 실물 시험 성공, 이번 변경 후 재확인 필요.
슬라이더2채널 ADC: 기존 실물 수신 성공, 중간값 입력 완료, 양끝 좌표 불확실.
위치 PI/앞뒤 목표 배분/피치 PID/통신 및 이상 정지: 로직 구현, 최종 실물 미검증.
조종기·IMU: 입력 경로와 관찰 모드 구현, 채널 방향/기준각/팀 통합 검증 필요.
RTOS: 태스크 분리 구현. 실제 부하에서 주기·스택 검증 필요.
엔코더: 이번 관찰 기능 구현. 모터 미도착으로 실물 입력 검증 불가.
