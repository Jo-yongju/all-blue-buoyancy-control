# 본체 통합

G431 바이너리를 F407에 그대로 사용할 수 없습니다. 제어 소스를 재사용하되 GPIO, 타이머, ADC, 시간 측정과 RTOS 연결은 본체에 맞춰 이식합니다.

| 태스크 | 우선순위 | 실행 기준 |
|---|---:|---|
| Control | 4 | 10 ms |
| Receiver | 3 | 수신 이벤트 |
| IMU | 2 | 데이터 준비 이벤트, 10 ms 보조 확인 |
| Console | 1 | 처리 후 1 ms 대기 |

제어 출력 간격을 우선 보장하고 PC 입출력은 낮은 우선순위로 처리합니다. IMU 보고 요청은 2.5 ms이며 제어는 최신 표본을 사용합니다. 데이터는 짧은 임계 구역에서 복사하고 명령은 큐로 전달합니다.

## 입력 연결

- SwC: 1000 UP / 1500 HOVER / 2000 DOWN
- CH4: 1000 기수 하강 / 1500 수평 / 2000 기수 상승. HOVER에서 사용
- 조종기 프레임은 300 ms, IMU 표본은 100 ms 신선도 기준
- IMU 각도는 도 단위, 수평 0, 기수 상승 양수로 보정

`examples/team_hooks.c.example`처럼 새 프레임마다 `TeamLink_PublishRadio`, 새 IMU 표본마다 `TeamLink_PublishPitch`를 호출합니다. 이전 값을 현재 시각으로 반복 게시하지 않습니다.

시작은 Observe → ready_to_arm 확인 → Arm 순서입니다. 명시적 STOP 이후 ARM을 자동 반복하지 않습니다. 송신기 전원 OFF 시험으로 failsafe 해석도 확인해야 합니다.

HOVER 진입 시 두 축을 중앙으로 이동시킨 뒤 피치 제어를 시작합니다. 앞뒤 모듈·센서 대응, IMU 부호, 피치 보정 방향과 게인은 실물 통합 시 확인할 항목입니다.

기구에서는 첫 너트 기어의 들림·마모가 남아 있습니다. PWM을 낮춘 것만으로 이 문제가 해결됐다고 판단하지 않았습니다.
